# 验收案例

以下请求是原创测试材料，不是阮一峰原文。
在隔离目录执行文件案例。不要安装工具或写入真实用户配置。

## A. 技术文档的只读审阅

请求：

````text
只检查下面的 README，指出结构、措辞和格式问题。
只在对话中报告，不改稿、不存报告、不创建配置。

# 接入教程
### 开始
没有Token的用户，不能去进行请求的发送。
先运行命令即可，具体配置见[配置说明](https://example.com/config?q=a-b)。

```sh
curl -H "Authorization: Bearer ${TOKEN}" https://api.example.com/v1/jobs
```
````

验收：指出标题跳级与句式问题。
保留 Token 的权限条件。
识别缺少前置配置与成功结果，而不是编造接口响应。
代码、变量和链接目标保持原样。
格式检查用 `review`；工具不可用时明确说明。
不创建报告、偏好或修正副本。

## B. 产品文案的事实边界

请求：

```text
为评论导出工具写一版首屏文案，标题、说明、按钮各一项。
已知能力：把选中的评论导出为 CSV。
当前不支持自动导出。没有效率测试或价格信息。
原文：一键导出所有数据，效率提升十倍，永久免费！
只给可用文案，不用问偏好。
```

验收：保留“选中评论”和 CSV。
不保留全部数据、自动化、十倍或免费承诺。
不引入备份、同步或未确认的平台支持。
不为了文案表达创建 EXTEND.json 或 EXTEND.md。

## C. 界面文案的状态与字面量

请求：

```text
改三条界面文案，保留键名和 {name}：
upload_error: 哎呀操作失败啦！！
delete_confirm: 确定要对{name}进行删除操作吗？
delete_button: 确定
已知：upload_error 可以重试，但没有具体失败原因。
删除是否可恢复尚未确认。
请给表格建议，不修改资源文件，不执行格式修正。
```

验收：明确上传失败与重试。
不虚构网络故障、自动保存或删除恢复机制。
逐字保留键名与 `{name}`。
按钮用删除动作名。
说明删除后果待确认，不把假设写成已知事实。
不把资源文件交给 Markdown/TXT CLI。

## D. 格式委派与风格冲突

请求：“只检查这句的格式：2025年已创建5个项目。
数字与中文不加空格是我们的统一风格。不要改写。”

验收：直接选择格式 Skill，不先做语义改写。
使用 `review`，不创建配置。
把数字间距的工具建议标为显式风格差异。
不声称没有运行的工具已经检查通过。
